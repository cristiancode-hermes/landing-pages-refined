# Accessibility (a11y)

Ship to WCAG 2.1 AA by default. These checks are cheap at write time and
expensive at retrofit time.

## While writing markup

```tsx
// ☠ div-button: no keyboard, no role, no focus, invisible to AT
<div className="btn" onClick={save}>Save</div>

// ✔ real button — keyboard & semantics free
<button type="button" onClick={save}>Save</button>

// ☠ icon-only button with no name
<button onClick={close}><XIcon /></button>
// ✔
<button type="button" onClick={close} aria-label="Close dialog"><XIcon aria-hidden /></button>
```

```tsx
// ✔ a labelled, validated input — the full pattern
<label htmlFor="email">Email</label>
<input
  id="email" name="email" type="email" autoComplete="email"
  aria-invalid={!!errors.email}
  aria-describedby={errors.email ? "email-error" : undefined}
/>
{errors.email && (
  <p id="email-error" role="alert">{errors.email}</p>
)}
```

- Interactive = focusable = real element: `<button>` for actions, `<a href>`
  for navigation. Placeholder is not a label.
- Every image: descriptive `alt`, or `alt=""` if decorative.
- Heading levels form an outline (one `h1`, no skips); landmarks (`nav`,
  `main`, `footer`) present.
- ARIA is a last resort: no ARIA beats wrong ARIA. Use it for **state**
  (`aria-expanded`, `aria-current`, `aria-invalid`), not to rebuild native
  semantics.

## Keyboard

```css
/* ✔ visible focus without annoying mouse users */
:focus-visible { outline: 2px solid var(--color-focus); outline-offset: 2px; }
/* ☠ never this without a replacement */
:focus { outline: none; }
```

- Tab through the whole feature yourself: focus visible everywhere, order
  follows visual order, no traps.
- Modals/menus: focus moves in on open, is contained while open, returns to
  the trigger on close; `Escape` closes. Use `<dialog>` or a headless
  library (Radix, React Aria, Angular ARIA) instead of hand-rolling:

```tsx
// ✔ native dialog gives focus containment + Escape for free
const ref = useRef<HTMLDialogElement>(null);
useEffect(() => {
  open ? ref.current?.showModal() : ref.current?.close();
}, [open]);
return (
  <dialog ref={ref} onClose={() => setOpen(false)} aria-labelledby="dlg-title">
    <h2 id="dlg-title">Confirm removal</h2>
    ...
  </dialog>
);
```

## Visual & dynamic

- Contrast: 4.5:1 body text, 3:1 large text/UI parts. Check disabled and
  placeholder grays — the usual offenders.
- Never color alone for state: error = red **+ icon/message**.
- Async updates that matter get announced:

```tsx
// polite live region for results counts / toasts
<div aria-live="polite" className="sr-only">{statusMessage}</div>
```

- Respect reduced motion:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; }
}
```

## Verify

```bash
npx playwright test a11y.spec.ts        # with @axe-core/playwright:
```

```ts
import AxeBuilder from "@axe-core/playwright";
test("checkout page has no critical a11y violations", async ({ page }) => {
  await page.goto("/checkout");
  const results = await new AxeBuilder({ page }).analyze();
  expect(results.violations.filter(v => v.impact === "critical")).toEqual([]);
});
```

Automated tools catch ~40%; the keyboard walkthrough above catches most of
the rest. Test the form's **error state**, not just its happy path.
